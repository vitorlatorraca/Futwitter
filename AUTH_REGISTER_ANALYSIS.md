## 3️⃣ When 400 Bad Request is Returned

The endpoint returns **400 Bad Request** in the following scenarios:

### **A. Zod Validation Errors** (lines 119-129)
**Triggered when**:
- `name` is missing, empty string, or less than 2 characters
- `email` is missing, empty string, or invalid email format
- `password` is missing, empty string, or less than 6 characters
- Any field has incorrect data type (e.g., `name` is a number)

**Response Format**:
```json
{
  "message": "<first validation error message>",
  "errors": [
    {
      "path": "<field.path>",
      "message": "<error message>"
    }
  ]
}
```

**Example**:
```json
{
  "message": "Nome deve ter pelo menos 2 caracteres",
  "errors": [
    {
      "path": "name",
      "message": "Nome deve ter pelo menos 2 caracteres"
    }
  ]
}
```

### **B. Duplicate Email** (line 72)
**Triggered when**: Email already exists in database

**Response**:
```json
{
  "message": "Email já cadastrado"
}
```

### **C. Other Errors** (line 137)
**Triggered when**: Any other error occurs (except DB/infrastructure errors)

**Response**:
```json
{
  "message": "<error.message> || 'Erro ao criar conta'"
}
```

### **D. Empty or Malformed Request Body**

**Empty Body** (`{}`):
- ❌ **Will fail** - Missing required fields (`name`, `email`, `password`)
- Returns 400 with validation error

**Malformed JSON**:
- ❌ **Will fail** - Express.json() will throw before reaching route handler
- Returns 400 with "Unexpected token" or similar JSON parse error

**Missing Content-Type**:
- ⚠️ **May fail** - Express.json() might not parse body correctly
- Could result in `req.body` being `undefined` or empty object

**Wrong Content-Type** (e.g., `text/plain`):
- ⚠️ **Will fail** - Express.json() won't parse body
- `req.body` will be `{}` or `undefined`
- Returns 400 with validation error
